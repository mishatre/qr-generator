# Контракт генератора QR-кодов: что обещано и что измерено

Этот файл - договор между компонентой (Rust), оберткой (`qr_QRCode`), набором тестов и
тем, кто всем этим пользуется. Все числа здесь либо измерены, либо помечены как
неизмеренные. Ссылки на файл есть в заголовках модулей обертки и кэша, поэтому его
содержание обязано совпадать с кодом.

## 1. Что возвращается в 1С

`СоздатьQRКод` возвращает **двоичные данные** (PNG). Это не упрощение, а ограничение
платформы: Native API не позволяет вернуть массив или структуру - документация прямо
запрещает `VTYPE_ARRAY` и `VTYPE_VARIANT` / `VTYPE_INTERFACE`. Двоичные данные - то
единственное, чем картинка доходит до 1С без промежуточного кодирования; строка
означала бы base64 и треть объема сверху.

Отказ передается не исключением компоненты, а **пустым результатом**: функция Rust
возвращает `Result<Vec<u8>, QrError>`, но наружу отдает пустой срез и текст причины,
а обертка превращает это в исключение с этим текстом.

## 2. Формат записи и проверочный код

Данные - строка вида

```
Тип | Код/Артикул | Серия | Срок | XXXXXXXXYYYY
```

где `XXXXXXXX` - идентификатор экземпляра, `YYYY` - проверочный код (он же визуальный,
он же последние четыре символа записи).

Правила, которые обязаны совпадать на обеих сторонах:

* алфавит кодов - `23456789ABCDEFGHJKLMNPQRSTUVWXYZ` (32 символа, без `0`, `1`, `I`, `O`);
* идентификатор экземпляра - 8 символов: 3 из них несут 5 случайных байт, остальное -
  разряды; источник случайности - операционная система, не 1С;
* проверочный код - 4 символа, первые 20 бит SHA-256 от **основы записи, то есть записи
  без самого кода**, включая идентификатор экземпляра;
* кодируется **UTF-8**, а не latin1, в отличие от сервиса-образца.

Векторы, закрепленные тестами (`rust/crates/addin/src/code.rs`):

| Основа | Код |
| --- | --- |
| `""` | `WGSE` |
| `a` | `TCDS` |
| `ORDER-2026-0001` | `6PFM` |
| `2\|2000020302\|0085F0226\|01022031\|5RCD6VPE` | `AX4R` |
| `2\|2000020302\|0085F0226\|01022031\|5RCD6VPEAX4R` | `NK5F` |
| `RUNZE-...\|09.03.2027\|1` (запись рабочего сервиса) | `EHY7` |

Идентификаторы: `00..00` -> `22222222`, `ff..ff` -> `ZZZZZZZZ`,
`0123456789` -> `26KNCTWB`, `deadbeef00` -> `VUQVXVS2`, `8000000000` -> `J2222222`.

## 3. Настройки отрисовки

Список имен возвращает `qr_QRCode.НастройкиПоУмолчанию(Язык)`; там же и значения по
умолчанию. Таблица ниже - то же самое в виде, пригодном для сверки с Rust.

| Русское имя | Английское имя | Ключ JSON | По умолчанию | Границы |
| --- | --- | --- | --- | --- |
| Размер | Size | `size` | 600 | 64..4096 |
| УровеньКоррекцииОшибок | ErrorCorrectionLevel | `errorCorrectionLevel` | `H` | `L`, `M`, `Q`, `H` |
| ЗонаПокоя | QuietZone | `quietZone` | 0 | 0..10 модулей |
| РазмерПодписи | LabelSize | `labelSize` | 0.3 | до 0.75 |
| ОтступПодписи | LabelMargin | `labelMargin` | 8 | - |
| СкруглениеПодписи | LabelRadius | `labelRadius` | 0.12 | - |
| СтрокПодписи | LabelRows | `labelRows` | 0 | 0 - подобрать |
| ЦветКода | Foreground | `foreground` | `#111111` | `#rgb`, `#rrggbb` |
| Фон | Background | `background` | `transparent` | `#rgb`, `#rrggbb`, `transparent` |
| ЦветПодписи | LabelColor | `labelColor` | `#000000` | то же |
| ФонПодписи | LabelBackground | `labelBackground` | `#ffffff` | то же |

Незнакомое имя настройки - ошибка, а не «приняли по умолчанию»: иначе вызывающий код
получит не то изображение, которое просил, и не узнает об этом. Значение вне границ
отвергает компонента, а не обертка: границы живут в одной реализации.

### Почему 0.3, а не 0.4

Подпись закрывает модули кода, поэтому ее размер ограничен не вкусом, а читаемостью.
Измерено декодером `rqrr` (тесты `rust/crates/addin/tests/generation.rs`):

| Символ | Размер подписи | Читается |
| --- | --- | --- |
| 25 модулей | 0.4 | нет (`DataEcc`) |
| 25 модулей | 0.35 | да |
| 25 модулей | 0.25, зона покоя 4 | да |
| 41 модуль | 0.4 | да |

Отсюда умолчание 0.3 и два теста-ограничителя: они падают, если кто-то поднимет
умолчание обратно или отнимет у кода зону покоя.

## 4. Кэш подключения компоненты

Общий модуль расширения не может объявлять переменные модуля (платформа отвечает
«Данный модуль может содержать только определения процедур и функций»), поэтому своего
кэша у обертки нет. Подключение выполняет `qr_QRCodeСерверПовтИсп` с признаком
`ReturnValuesReuse = DuringSession`: платформа вызывает его функцию один раз за сеанс и
запоминает результат.

Так устроена конфигурация «Управление нашей фирмой»: рядом с модулем
«ГенерацияШтрихкода» лежит модуль «ГенерацияШтрихкодаСерверПовтИсп» с единственной
функцией, которая вызывает подключение из основного модуля (`docs/examples`).
Последовательность вызовов платформы при этом остается в одном месте -
`qr_QRCode.ПодключитьКомпоненту`, а модуль кэша только вызывает ее.

**Что не измерено.** Работает ли признак в расширении конфигурации так же, как в
конфигурации. Проверить это может только сборка расширения:

```
tests/bsl/run-tests.sh --build-only     # tier 1, лицензия 1С не нужна
```

Если платформа не примет признак, сборка упадет сразу, а не в сеансе. Если признак не
сработает, результат останется верным - функция просто вызовет подключение, то есть
изменится только скорость. Проверить факт кэширования из BSL нельзя: для этого нужно
измерять время вызова, а это тест на секундомере, а не на контракте.

## 5. Безопасный режим

Платформа запрещает загрузку и подключение внешних компонент, пока установлен
безопасный режим, и отключить его из процедуры, которая его не устанавливала, нельзя.
Поэтому функции обертки нельзя вызывать из кода, работающего в безопасном режиме;
`ПодключитьКомпоненту` говорит об этом текстом исключения. Так же считает и документация
YAxUnit: тестовой базе для запуска набора нужно снять признак с расширения.

## 6. Имена

Имена в коде следуют словарю учетной системы, для которой сделан проект: латиница внутри
имени - часть терминологии, а не вставка чужого алфавита. Отсюда `СоздатьQRКод`,
`КомпонентаQRКода`, `ПодключитьКомпонентуQRКода`, `НастройкиJSON`, `ЗаписатьJSONЗначение`,
`ИмяRU` и `ИмяEN`. Так же написаны модули самой 1С: в
`docs/examples/ГенерацияШтрихкода.bsl` есть `ДанныеQRКода` и `УровеньКоррекцииQR`.
Проверка `LatinAndCyrillicSymbolInWord` имена этого вида считает смешением алфавитов:
измерено, что она срабатывает на `ДанныеQRКода` в строке 160 этого же файла.

Поэтому проверка отключена в тех модулях, где такие имена есть - `qr_QRCode`,
`qr_QRCodeСерверПовтИсп`, `qr_QRCodesTests` - собственным средством сервера:

```
// BSLLS:LatinAndCyrillicSymbolInWord-off
```

Отключение стоит в самих модулях, а не в файле конфигурации, потому что параметры
диагностик из файла конфигурации CLI не применяет (измерено, см. раздел «Диагностики»).
Строка проверена тем же прогоном: без нее диагностика выдается, с ней - нет.

Одно имя пришлось выбрать по результату проверки орфографии, а не по терминологии:
`НастройкиВJSON` она считает опечаткой в слове «ВJSON», а `НастройкиJSON` -
нет. Выбран второй вариант.

## 7. Комментарии к процедурам и функциям

Документирующие комментарии оформлены по стандарту 1С «Описание процедур и функций»
(#std453), области модулей - по стандарту «Структура модуля» (#std455). Страницы этих
стандартов лежат в `docs/1c-docs` и в репозиторий не коммитятся: текст принадлежит 1С,
а в репозитории достаточно ссылки на номер стандарта.

Что взято из стандарта:

* секции «Описание», «Параметры», «Возвращаемое значение», «Пример» - в этом порядке;
* описание начинается с глагола («Возвращает…», «Подключает…»), а не с имени метода;
* факт отказа описан в секции «Описание» («Если проверка не проходит - генерируется
  исключение»), а не абзацем после секций;
* структуру, которую возвращает функция-конструктор, описывает сам конструктор
  (`НастройкиПоУмолчанию`); в остальных местах вместо перечисления полей стоит ссылка -
  `Настройки - Структура - см. qr_QRCode.НастройкиПоУмолчанию.`;
* дополнительные типы параметра - строками с ведущим дефисом (`- Неопределено - …`);
* тип элементов массива - через «Из» (`Массив Из Структура`);
* пример вызова называет общий модуль (`qr_QRCode.НастройкиПоУмолчанию()`) и показывает,
  что приходит на вход и что получается на выходе.

Два намеренных отклонения от стандарта:

* **Дефис вместо длинного тире.** В примерах стандарта тип отделен знаком «–», а в коде
  1С и во всем ее инструментарии - обычным дефисом. Принят дефис: длинное тире
  диагностика `InvalidCharacterInFile` считает недопустимым символом, а разбор
  документирующих комментариев в сервере ожидает именно дефис.
* **Тип остается в слоте типа.** В 5.2.2 и 5.2.6 стандарт допускает запись
  `ПараметрыЗаполненияЦен - см. ЦенообразованиеСервер.ПараметрыЗаполненияЦен` - без типа.
  Проверено: сервер такой параметр считает неописанным (`MissingParameterDescription`,
  «Add description for the Настройки parameter»). Поэтому ссылка на конструктор стоит в
  описании, а в слоте типа остается `Структура`. Требование стандарта - не перечислять
  поля, а сослаться на конструктор - при этом выполнено.

Диагностика `MissingParameterDescription` требует описания для каждого параметра, поэтому
у параметров, где имя и тип говорят все, описание все равно есть: короткое, повторяющее
тип. Стандарт в 5.2.1 писать его не требует.

## 8. Диагностики BSL Language Server

Прогон делается так (версия 1.0.7, CLI из расширения VS Code):

```
B="$HOME/Library/Application Support/Code/User/globalStorage/1c-syntax.language-1c-bsl/bsl-language-server/v1.0.7/bsl-language-server.app/Contents/MacOS/bsl-language-server"
"$B" analyze -c "$PWD/.bsl-language-server.json" -s "$PWD/src" -r json -o /tmp/bsl-out -q
"$B" analyze -c "$PWD/.bsl-language-server.json" -s "$PWD/tests/bsl" -r json -o /tmp/bsl-out -q
```

Кроме разобранного ниже, одна проверка отключена намеренно: `LatinAndCyrillicSymbolInWord`
(раздел «Имена»).

Состояние на момент последней правки: `tests/bsl` - ноль диагностик, `src` - три, и
все три разобраны ниже и **не устранимы в коде**:

* `CommonModuleInvalidType`, дважды (по разу на модуль). Срабатывает на любой общий
  модуль, зарегистрированный в `Configuration.xml` расширения. Измерено: диагностика
  исчезает, если убрать `Configuration.xml`, и остается, если переименовать модуль в
  `qr_QRCodeСервер`; у соседнего проекта (`yp_YAML`) она тоже есть. Признаки модулей при
  этом выставлены корректно: `Server = true`, остальные контексты выключены.
* `Typo` на `#ffffff`. Значение цвета - не слово, орфографическому словарю его принять
  нечем. Измерено, что сокращенная запись `#fff` вызывает ту же диагностику, поэтому
  оставлена полная, совпадающая с умолчанием компоненты.

**Исключить их через конфигурацию нельзя.** Измерено, что CLI 1.0.7 не применяет
параметры диагностик из файла конфигурации вообще: при `LineLength.maxLineLength = 5`
(ложное значение, которое обязано дать десятки срабатываний) не появляется ни одной
диагностики `LineLength` - ни при ключе верхнего уровня, ни внутри `diagnostics`, ни
внутри `diagnosticParameters`, ни при передаче файла через `-c`, ни при поиске от
`-w`. Комментариев JSON-парсер сервера тоже не принимает (падает с
`ALLOW_COMMENTS not enabled`). Поэтому исключения не выдумываются, а разбираются здесь:
файл `.bsl-language-server.json` остается минимальным и ничего не обещает.

Для сравнения, тот же прогон по коду самой 1С и по соседнему проекту:

| Код | `docs/examples` (1С, «Управление нашей фирмой») | `yaml-parser` |
| --- | --- | --- |
| Всего | 39 | 41 |
| В том числе | LineLength 7, Typo 6, MagicNumber 4, CognitiveComplexity 3, SemicolonPresence 3, IfElseIfEndsWithElse 2, ... | InvalidCharacterInFile 18, MissingReturnedValueDescription 8, Typo 5, ... |

Так что и «длинные строки», и «возможно, опечатка» - диагностики, с которыми
поставляемый код 1С живет. Здесь их нет за одним исключением, и это исключение описано.
