# Компонента «Генератор QR-кодов»: что забрать и как подключить

Документ для разработчика 1С: готовые артефакты, способы подключения, публичный интерфейс
модуля и границы применимости. Внутреннее устройство, принятые решения и доказательства
лежат в `docs/plan/`; здесь только то, что нужно, чтобы начать пользоваться.

Компонента принимает данные, текст подписи и настройки, а возвращает изображение - PNG в
виде двоичных данных 1С. Подпись рисуется в середине кода на подложке со скругленными
углами (в учетных записях это проверочный код - последние четыре символа строки данных).

## 1. Артефакты

| Файл | Что это | Размер |
| --- | --- | --- |
| `QrGeneratorNative.zip` | Архив внешней компоненты: `manifest.xml`, `QrGenerator_linux_x86_64.so`, `QrGenerator_win_x86_64.dll`. Именно его содержимое загружается в общий макет с двоичными данными. | 1 714 395 |
| `QrGenerator.cfe` | Расширение конфигурации: общий модуль `qr_QRCode` (публичный интерфейс), общий модуль `qr_QRCodeСерверПовтИсп` (повторное использование подключения) и общий макет `qr_QrGeneratorNative` с этим архивом внутри. | 1 807 019 |
| `qr_QRCode.bsl` | Текст обертки отдельным файлом - чтобы вставить в свою конфигурацию, не разбирая XML-выгрузку расширения. | 26 590 |
| `qr_QRCodeСерверПовтИсп.bsl` | Текст модуля кэша подключения. Нужен вместе с оберткой: обертка вызывает его. | 2 150 |

Архив компоненты и расширение - разные вещи: архив подключается к сеансу платформой
(`AddIn.QrGenerator.QrGenerator`), а расширение содержит модули, которые им пользуются.
Можно взять одно расширение - оно несет архив внутри себя; можно взять только модули и
собрать расширение (или общие модули своей конфигурации) самому.

## 2. Быстрый способ: поставить расширение

1. Конфигуратор -> «Расширения конфигурации» -> «Добавить из файла» -> `QrGenerator.cfe` ->
   «Применить».
2. В свойствах расширения снять флажки **«Безопасный режим»** и **«Защита от опасных
   действий»**. Пока безопасный режим установлен, платформа не подключает внешние
   компоненты, и вызов обертки вызывает исключение об этом.
3. Проверить, что компонента поднялась: `qr_QRCode.ВерсияКомпоненты()` возвращает строку
   версии, например `0.1.0`.

Расширение объявлено как «дополнение» (`AddOn`), поэтому оно ставится на любую
конфигурацию, а не только на конкретную.

## 3. Своими общими модулями, без расширения

Если расширение не подходит, модули переносятся в конфигурацию вручную:

1. Общий модуль `qr_QRCode`: серверный, остальные контексты выключены.
2. Общий модуль `qr_QRCodeСерверПовтИсп`: серверный, у него включено **«Повторное
   использование возвращаемых значений» = «В течение сеанса»**. Это кэш подключения: без
   него компонента подключается при каждом вызове (то есть работает, но медленнее).
3. Общий макет `qr_QrGeneratorNative` с типом «Двоичные данные»: в его тело загружается
   содержимое `QrGeneratorNative.zip` целиком, как есть. Платформа читает `manifest.xml`
   внутри архива, выбирает файл под свою операционную систему и загружает его оттуда.
4. Перенести текст модулей из файлов `.bsl`.

## 4. Публичный интерфейс

Все функции вызываются на сервере. `Данные` - то, что кодируется, а `Текст` - подпись в
середине.

| Функция | Что делает |
| --- | --- |
| `СоздатьQRКод(Данные, Текст, Настройки)` | Возвращает изображение: двоичные данные PNG. Пустая строка данных и данные, не помещающиеся в код наибольшего размера, вызывают исключение с причиной. |
| `НастройкиПоУмолчанию(Язык)` | Возвращает структуру настроек отрисовки со значениями по умолчанию; имена свойств по-русски (`"ru"`, по умолчанию) или по-английски (`"en"`). |
| `ВизуальныйКод(Запись)` | Последние четыре символа строки данных - то, что печатается подписью. |
| `ПроверочныйКод(Основа)` | Считает проверочный код по основе записи (запись без самого кода). |
| `КодВерен(Запись)` | Проверяет, что код в конце записи совпадает с пересчитанным. |
| `ИдентификаторЭкземпляра()` | Восемь символов алфавита кодов - идентификатор для новой записи. |
| `ВерсияКомпоненты()` | Версия компоненты - для журнала регистрации и обращений в поддержку. |
| `ПолноеИмяОбъектаКомпоненты()` | Имя объекта после подключения: `AddIn.QrGenerator.QrGenerator`. |
| `ПодключитьКомпоненту(Местоположение)` | Подключает компоненту и возвращает ее экземпляр. Нужна, если подключать нужно из необычного места или держать объект у себя. |

## 5. Примеры

```bsl
// Код для записи: данные целиком, подпись - проверочный код записи.
Запись = "2|2000020302|0085F0226|01022031|5RCD6VPEAX4R";
Изображение = qr_QRCode.СоздатьQRКод(Запись, qr_QRCode.ВизуальныйКод(Запись));
// Изображение - двоичные данные PNG; далее картинка, файл или вложение.
Картинка = Новый Картинка(Изображение);
```

```bsl
// Свои настройки: белый фон и подпись поменьше - вариант для печати.
Настройки = qr_QRCode.НастройкиПоУмолчанию();
Настройки.Фон = "#ffffff";
Настройки.РазмерПодписи = 0.25;
Изображение = qr_QRCode.СоздатьQRКод(Запись, "AX4R", Настройки);
```

```bsl
// Много кодов подряд: компоненту можно подключить один раз и держать у себя.
Компонента = qr_QRCode.ПодключитьКомпоненту();
Для Каждого Запись Из ЗаписиКПечати Цикл
	Изображение = Компонента.СоздатьQRКод(Запись, qr_QRCode.ВизуальныйКод(Запись), "");
	// ...
КонецЦикла;
```

## 6. Настройки

Список имен возвращает `qr_QRCode.НастройкиПоУмолчанию()`: она же служит описанием настроек,
поэтому дублировать их здесь не нужно. Значения по умолчанию подобраны под печать:

| Настройка | По умолчанию | Смысл |
| --- | --- | --- |
| `Размер` | 600 | Сторона квадратного изображения в пикселях (64..4096). |
| `УровеньКоррекцииОшибок` | `#H` | Избыточность кода: `L`, `M`, `Q` или `H`. `H` - потому что подпись закрывает модули. |
| `ЗонаПокоя` | 0 | Пустая зона вокруг кода в модулях: нужна, если код печатается вплотную к краю. |
| `РазмерПодписи` | 0.3 | Сторона подложки подписи как доля стороны изображения. 0.4 на символе из 25 модулей уже не читается. |
| `ОтступПодписи` | 8 | Отступ от края подложки до текста в пикселях. |
| `СкруглениеПодписи` | 0.12 | Скругление подложки как доля ее стороны. |
| `СтрокПодписи` | 0 | Число строк подписи; 0 - подобрать автоматически. |
| `ЦветКода` | `#111111` | Цвет модулей. |
| `Фон` | `transparent` | Цвет фона: `#rrggbb` или `transparent`. Прозрачный - чтобы код ложился на любую поверхность. |
| `ЦветПодписи` | `#000000` | Цвет текста подписи. |
| `ФонПодписи` | `#ffffff` | Цвет подложки. `transparent` здесь означает не «невидимая подложка», а отверстие: модули под подписью удаляются, и на их месте остается прозрачность. |

Незнакомое имя настройки вызывает исключение, а не молчаливое «взяли значение по
умолчанию»: иначе вызывающий код получил бы не то изображение, которое просил.

## 7. Границы применимости

* **Безопасный режим.** Внешнюю компоненту в нем подключить нельзя; обертка говорит об
  этом текстом исключения. Подключайте компоненту до входа в безопасный режим.
* **Один код за вызов.** Функция возвращает одно изображение; пакетной генерации нет.
  Много кодов подряд быстрее через один подключенный объект (пример в разделе 5).
* **Размер подписи.** Подпись закрывает модули, и коррекция восстанавливает только часть из
  них. Предел измерен: 0.4 на символе из 25 модулей не читается, 0.35 читается, 0.25
  читается и при зоне покоя 4. Отсюда умолчание 0.3.
* **Пустые данные - ошибка.** Код без содержимого сканируется в пустую строку, и отличить
  его от исправного снаружи нельзя.
* **Размер картинки.** 600 пикселей с подписью - около 11 КБ PNG, 1024 пикселя - около
  20 КБ; проверено тестом, что такое изображение помещается в хранилище значений.
* **Платформа.** Компонента собрана под 8.3.24 (проверено на 8.3.24.1667), Windows x86_64
  и Linux x86_64. Для других платформ нужна своя сборка.
* **Только сервер.** Общие модули объявлены серверными: на клиенте изображение пришлось бы
  передавать отдельно.

## 8. Как пересобрать

```sh
# Библиотеки: обе цели сразу, Windows собирается кросс-компилятором.
# Требуется nightly-тулчейн с rust-src - сборка std из исходников дает основную экономию.
tools/native/build-addin.sh

# Архив компоненты: manifest.xml + обе библиотеки, с проверкой по манифесту.
tools/native/pack-addin.sh

# Расширение: макет с архивом внутри, компиляция без лицензии 1С (ibcmd).
tools/1c-release/compile-extension.sh

# Набор для передачи: архив, расширение, тексты модулей и этот документ.
tools/1c-release/build-handoff.sh
```

Сборка библиотек возможна только там, где есть линковщики обеих целей: дома это
devcontainer проекта, а не хост-машина. Оба релизных профиля и измеренные размеры описаны в
`docs/plan/index.md` (T001).
